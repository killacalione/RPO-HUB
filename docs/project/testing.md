# Testing and evidence

Foundation checks: public data shape, permitted evidence states, tracked/public file boundaries, recognizable secret/local-path patterns, local Markdown links, seven TOML/card mirrors, source script syntax and deterministic site output. Run `npm run check` then `npm run build`; browser review checks desktop/mobile reflow, keyboard navigation, key links and release metadata. Live Pages deployment and local tests are separate evidence gates.

Original input archive bytes/hashes and merge classification are recorded in [merge evidence](../provenance/MERGE-REPORT.md). The earlier prototype's structural test and REA replay cover its old one-world navigation only; no S1 or application safety pass follows.

S1 remains unstarted. Its required checks cover dual-authoring bundle parity, two-world personalization/save/travel/reload/export, requested visibility, invalid/failed/duplicate travel, corrupt imports, storage failures, hostile interpreted scripts, bridge/renderer bounds, disposal and desktop keyboard/reduced motion. Actual commands/environment/revision and unavailable checks belong in the work ledger.

Later online stages require authoritative access denial, changed-client tests, voice delivery/lifecycle, publisher revocation, cohort/guardian/country rules and independent human operational/legal/security readiness review. Synthetic/local tests do not prove physical devices, actual ages, global compliance or production capacity. See [S1 brief](../planning/S1-IMPLEMENTATION-BRIEF.md).
