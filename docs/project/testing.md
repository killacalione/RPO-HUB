# Testing and evidence

Foundation validation runs `npm run check`, `npm run build` and `git diff --check`. The checker covers structured product status, public-file boundaries, recognizable secrets/local paths, local Markdown links, seven TOML/card role mirrors, JavaScript syntax, roadmap/requirements consistency, all five generated routes, the nine-theme registry, generated palettes/scenes, unique SVG IDs and fragment references, picker/navigation/motion contracts, scene animation limits, route resource budgets and the exact curated Pages output. Each route's uncompressed HTML, CSS, JavaScript and favicon must remain at or below 300 KiB.

For the atmosphere redesign, review the built site rather than source alone. Exercise every theme across all five routes and reload; check the legacy theme IDs and session keys, invalid stored themes, unavailable storage, theme restoration before the stylesheet and fallback select. Verify the dialog opens, all nine cards and Done are reachable at phone size, radio arrow-key selection works, Space/Enter activates controls, selection applies immediately, hover does not select, Escape/close/Done preserve the choice and return focus, and the skip link, current navigation, visible focus and four Home portals work by keyboard.

Measure Home at 1280×720, 1440×900 and 375×812, plus 320px reflow and actual 200% browser zoom. Check all five routes, normal detail-page scrolling, selected scene per page, still previews/inactive scenes, readable evidence/status badges and no horizontal overflow. Record zoom if only a CSS-scale simulation was available; it is not equivalent to browser zoom.

With normal motion, verify Pause and Resume stop/restart scene animation and preserve the explicit `rpo-hub-pause-motion` choice through navigation. Verify reduced motion on load and after a live operating-system preference change, then remove the preference and confirm the stored user choice is unchanged. Hidden-tab suspension must pause animation without persisting a choice. Check animation element budgets (Home ≤24, detail ≤8; phone limits halve those caps), reduced-motion behavior, page-entry reveal, static card previews, console/page errors, failed requests, unexpected navigation, failed local assets and bundle parity between preview, clean build and deployed `/The-Oasis/` output. Unavailable device/browser controls are explicit gaps, not passes.

Live Pages deployment and local checks are separate evidence gates. A passing build does not establish current GitHub Actions, a live release revision or deployed-content parity. Verify the release record against the exact merged commit and compare route/shared-asset responses with a clean build. If the available browser prefers reduced motion, report that the normal-motion pause/resume interaction could not be exercised there.

Original input archive bytes/hashes and merge classification are recorded in [merge evidence](../provenance/MERGE-REPORT.md). S1 remains unstarted. Its application checks cover local onboarding (new profile cannot bypass first Hub spawn), dashboard availability, player-owned avatar/outfit, appearance incompatibility, optional Home and requested visibility, returning Resume/Always Hub/Always Home, exact saved world/version/frame/XYZ/facing/confirmed revision and recovery; plus dual-authoring bundle parity, two-world personalization/save/travel/reload/export, invalid/failed/duplicate travel, corrupt imports, storage failures, hostile interpreted scripts, bridge/renderer bounds, disposal and desktop keyboard/reduced motion. A save counts only after acknowledged completion; crash recovery is limited to the last confirmed record. Actual commands/environment/revision and unavailable checks belong in the work ledger.

Later online stages require authoritative access denial, changed-client tests, voice delivery/lifecycle, publisher revocation, cohort/guardian/country rules and independent human operational/legal/security readiness review. Synthetic/local tests do not prove physical devices, actual ages, global compliance or production capacity. See [S1 brief](../planning/S1-IMPLEMENTATION-BRIEF.md).
