# Portable S1 implementation handoff

Prepared after seven interview rounds, 2026-10-14. Use this with Codex, Hermes, Copilot or another capable coding agent in the actual project workspace. It is a copyable implementation assignment, not evidence of execution. The planning package has no application. The owner prefers cloud models and may switch clients/providers or use compatible local models.

## Entry prompt

```text
Implement the internal S1 prototype of this open-world hub project. Work from
the current files and user instructions; preserve existing work and recorded
requirements. Read AGENTS.md, PROJECT-BRIEF.md, docs/planning/WORK-STATE.md,
docs/planning/S1-IMPLEMENTATION-BRIEF.md, docs/planning/DEMO-EXPERIENCE.md,
docs/planning/SPACE-ACCESS.md and the relevant architecture/security/testing
docs. Use roles/implementation-engineer.md as the portable scoped role when
needed. Do not assume Codex-specific role files load in another client.

First inspect the actual destination, instructions, Git/working state,
runtime/package tools, client/model and available file/shell/browser tools.
Record the task and one writer in WORK-STATE.md. In an existing repository,
use an isolated branch/worktree when needed and preserve pending user edits.
If only the planning package exists, create a separate internal S1 spike
folder and keep the original package/provenance intact. Existing task
authorization governs routine reversible work; ask only for missing facts
that actually block the active task. Do not alter global machine settings.

Choose and pin a bounded tested spike stack from current primary sources and
the actual environment. JS/TS, Babylon, desktop Monaco and QuickJS-in-Wasm
worker containment are candidates, not proven production decisions.
Implement one versioned World SDK/project contract for local authoring and
the integrated browser editor. Include source/errors/logs, Run/Stop,
import/export and validation. Execute guest scripts in the isolated
interpreted runtime with independent termination and bounded host commands;
no native host eval or Node vm security claim.

Build two original small scenes for the selected journey: explore, choose
an approved color and place/arrange a prop, save/export, activate a portal,
interact in the second world, and return with choices intact. Include owner
visibility selection at creation as a local requested preference. Preserve
it and personalization through travel, successful save/reload and export/
import. Separate immutable template/source from validated personal state.
Private/Invite-only/Public semantics and scene themes are design proposals;
there are no real online account or access grants in this local prototype.

Handle invalid/duplicate/failed travel, failed saves and corrupt imports
with usable recovery and a persistent Return home. Test real hostile guest
cases, bridge/renderer budgets, resource disposal, bundle parity and actual
desktop keyboard/reduced-motion UI behavior. Record exact commands and
results. An unavailable device/tool/dependency is an explicit gap, never a
pass. The first online text/proximity/party voice, trusted publishing and
worldwide child/cohort operation remain later milestones.

Use available entitled model routes within the existing budget. For a new
or changed route, verify structured tool calls and result handling in a
disposable fixture. Optional REA source-analysis setup is separate and must
use the actual client's supported configuration; no native paid provider
is needed for this assignment. Shared files carry the project across agents.

Before a model/client change or at the end, update WORK-STATE.md with current
source root/revision, owned and changed files, actual checks, decisions,
blocked items and the next concrete step. Stop or finish active processes
before transferring the writer. Return the runnable source, setup commands,
tested environment, evidence and limitations. Do not claim global device,
age/privacy, runtime-security or release readiness from the local spike.
Do not publish/deploy, collect child data, activate billing, paid inference,
payments or record media as part of S1.
```
