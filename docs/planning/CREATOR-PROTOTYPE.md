# Internal code creator precursor

Round two selected code and scripting, replacing the visual scene-composer-first proposal. The first online release remains public and supports children, teens and adults. Low cost remains a requirement. This file describes a proposed internal precursor, not a completed public service.

Candidate result: a versioned World SDK with two original code-authored worlds, permitted interaction events, isolated Run/Stop preview, logs/errors and local project export/import. JavaScript/TypeScript with a Babylon renderer and QuickJS-in-Wasm worker runtime is a candidate requiring revision-pinned hostile tests. Both local source/VS Code and an integrated browser editor are required from start. Candidate Monaco desktop editor plus shared SDK/build/bundle validation; phone editor support must be designed separately.

Bundle small original/CC0 assets and dependencies. Avoid accounts, automatic uploads, cloud saves, remote AI and telemetry in the internal experiment. Verify actual runtime network/data behavior. Browser autosave is convenience, portable export is recovery, and no cloud sync is claimed. Local file/JS execution does not prove safe public code hosting.

The spike must prove a creative interaction and shutdown/permission/resource behavior together. Guest scripts submit validated commands, not unrestricted browser/engine/server access. Renderer, host callbacks, queues and server state have independent limits. No economy authority or private account data reaches scripts. Review [WORLD-SDK.md](WORLD-SDK.md) before code.

First-public-release scope is in [PUBLIC-RELEASE.md](PUBLIC-RELEASE.md). A private test is a milestone toward it, not an adult-only/private replacement. Actual language/runtime/API/editor implementation, trust/age/contact rules, operations, grants and hardware remain Unknown. Text/proximity/party voice and direct trusted publishing are confirmed. See [v0.1](V0.1-SPEC.md). See [roadmap](ROADMAP.md), [cost plan](COST-PLAN.md), [decisions](DECISIONS.md) and [sources](../research/SOURCES.md).

## Round-five selected creative loop

Visitors explore, personalize spaces and travel through portals. Two proposed scenes show approved color/prop changes, save/export, outbound travel and return with configuration intact. Both creator coding paths remain required. Browser convenience storage, local drafts and failed saves/imports need visible recovery; source and visitor configuration are separate. Exact personal-space visibility and shared editing remain open. See [demo design](DEMO-EXPERIENCE.md).
