# First public all-age creator release

**Requirements from rounds one/two/three/four:** Creators build/personalize worlds through code and scripting; the first online release supports children, teens and adults with public sharing and social interaction; prefer free/lowest-cost resources. Both coding paths, text/proximity/party voice and direct trusted publishing are confirmed. Worldwide first availability, age-group child public communication and owner limited maintainer capacity are selected. Exact country/cohort/trust/assurance/live-operations details remain open; no app exists.

## Proposed first public journey

A creator uses local or browser code tools to test a versioned world; a trusted publisher releases a valid bundle directly and receives a public world page. Eligible visitors discover publicly listed worlds, join shared rooms, see other participants and use text, proximity voice and party/group voice. Age/content/parent/contact permissions determine what each participant can access and disclose. Public browsing/social participation are preserved; an internal/invited test is preparation, not a private-only replacement release.

## Decisions required before implementation

| Decision | Why it changes scope |
|---|---|
| Shared coding contract | Both local and browser coding selected; choose editor/compiler/runtime implementation and test bundle parity |
| Trust policy | Direct trusted publishing selected; choose who grants/suspends it and minor-creator eligibility |
| Communication permissions | Text/proximity/party voice selected; decide age/contact routes and prove delivery enforcement |
| Age/contact permissions | Public group participation does not define adult-child DMs, invites or sensor permissions |
| Creator rights and SDK capabilities | Uploaded scripts/assets need provenance, bounded execution and versioned permissions |
| Operations | Assign publication/report/incident/removal owners; free infrastructure does not supply human response |

## Proposed launch controls to evaluate

Use original/rights-cleared worlds, a public directory, shared presence and requested text/world/party voice with trusted direct publishing. Provide block/mute/report, clear AI labels, role-based moderation and a world pause/quarantine path. Routine human review for each trusted release is superseded; automated checks, runtime boundaries and moderator revocation remain proposed enforcement. Supporting public sharing does not require instant unreviewed script execution or unrestricted direct contact.

Review child-directed/mixed-audience classification, all collection/disclosure via accounts/chat/code/assets/logs/processors, parent notice/verifiable consent where required and parent review/deletion/revocation. Educational provider benefits do not establish school parental-consent authority. Rights/DMCA and applicable NCII removal workflows are launch operations, not merely document names. See [legal readiness](../legal/LEGAL-READINESS.md).

## Release evidence

Creator publishes an approved version; eligible visitor discovers/joins; denied roles cannot publish/read private records; child/teen/adult and parent flows behave as reviewed; communication/block/report work; a world can be quarantined or rolled back; runtime/resource limits and host bridge pass pinned adversarial tests; actual free-tier exhaustion behavior is documented. No release date, participant capacity, cost guarantee or legal approval is established.

## Round-six personal-space joins

Owner-chosen visibility is required at creation. Public discovery and joins use current platform eligibility; private/invited spaces need protected listing/configuration/assets, accepted grants and live revocation. Visibility is separate from editing and publishing trust. Invitations cannot bypass age/guardian/contact/country/block policy. See [space access](SPACE-ACCESS.md).
